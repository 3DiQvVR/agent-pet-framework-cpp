# 已确认缺陷的修复与验证

本次对应代码审查确认的七项缺陷。

| 缺陷 | 修复 | 回归证据 |
|---|---|---|
| 静态资源 / Live2D 上传可越过根目录 | 拒绝带根路径、盘符、反斜杠、NUL 和父目录组件；解析现有目录链接后验证目标仍在允许目录内 | C++ 路径用例；HTTP 根路径/编码路径攻击、Windows junction、正常上传和下载 |
| 保存数据库先删原文件 | 同目录独立临时文件，Windows 写入刷新后原子替换；替换失败保留原件和完整候选文件 | 正常覆盖、目录保护、Windows 文件被占用时原件及候选内容保留 |
| 历史截断拆散工具消息 | 工具请求及全部结果作为一个保留/移除单元，丢弃旧历史中不完整的工具消息组 | 历史条数截断、完整/不完整多工具组、预算截断 |
| 流式中断当作成功 | 分离增量 SSE 解码器；传输读取失败直接报错；EOF 需要终止信号；完整工具参数校验通过后才交给 Agent | 逐字节 UTF-8 / CRLF、usage-only 尾块、缺结束信号、无效 JSON、不完整工具参数；本地 WinHTTP 实际断流 |
| 消息预算被突破 | 超长用户输入返回 `context_limit`，每轮请求前移除旧消息组、缩短工具结果；仍无法容纳时停止请求 | 10000 字节用户输入、大工具结果、多轮请求成本断言 |
| 截断破坏中文编码 | 共用 UTF-8 边界截断函数，截断标记也计入预算；用于系统提示、工具结果、Mock 记忆参数及 CLI 显示等 | 中文和四字节字符的不同字节边界；各轮模型输入有效性检查 |
| CLI / Web 记忆范围不一致 | 根据会话角色卡解析 character/session 范围，Web 按当前会话请求；切换会话后丢弃旧响应 | HTTP 和 CLI 双范围测试、Web 实际加载函数及过期响应检查 |

消息预算 `max_prompt_chars` 沿用 UTF-8 字节与消息元数据成本计算，不能等同于服务端的 token 上限，也不包含工具 schema。预算不足时会明确返回 `context_limit`；不会截短用户原文后静默提交。工具内容可在当前请求中缩短，保留完整的调用关系。

Windows 文件替换使用 `MoveFileExW` 的同卷替换；POSIX 使用同目录 `rename`。替换失败的候选文件名为 `<原路径>.<uuid>.tmp`，错误信息会指出其路径。此机制避免先删除原件导致的数据丢失窗口，不宣称能抵御所有磁盘硬件故障。

运行 C++ 验证：`ctest --test-dir build -C Release --output-on-failure`。
运行 Windows 端到端验证：`node tests/runtime_regression.mjs <实际 petcore.exe 路径>`。均使用模拟数据，无需线上模型密钥。
