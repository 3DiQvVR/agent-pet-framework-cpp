# 长期记忆与遗忘曲线

长期事实采用艾宾浩斯遗忘规律的工程近似：`R(t) = 1 / (1 + t / S)`。

`t` 是距离上次有效学习或回忆的小时数，`S` 是记忆半衰期（小时）。这是先快后慢的幂律曲线：初始 `S = 24`，保持度在 0、24、48、168 小时分别为 100%、50%、33.3%、12.5%。这些默认参数用于桌宠体验，并非人体记忆的通用测量值。研究依据：[Murre & Dros (2015)](https://doi.org/10.1371/journal.pone.0120644)。

## 检索和复习

- 检索分数为原有关键词/CJK 双字相关度乘以当前保持度。保持度低于 5% 的事实暂时不返回；满足下述清理条件后从长期事实数据库永久删除。
- 普通聊天按角色卡的 `memory.scope` 检索最多 5 条相关事实，在提示词预算内加入完整事实。禁止 `recall` 或要求其审批的策略也会阻止自动检索。
- 自动检索只有在事实实际加入提示词、且模型成功响应后才计作复习；显式调用 `recall` 时只复习返回的条目。空查询浏览、预览、无匹配、零数量和预算放不下的事实均不强化。
- 复习间隔至少 1 小时。有效复习后，`S_new = min(8760, S * (2 - R))`，再把计时起点移到当前时间。这模拟间隔复习的效果，强度最多为 365 天；程序关闭期间也会遗忘。
- 再次 `remember` 相同内容按上述规则强化，尚未删除的事实可恢复；已删除的事实必须重新提供内容，并作为新记忆保存（新 ID、24 小时半衰期、复习次数为零）。同一 key 的内容更正也会重置强度。
- 相同数据和时间的检索结果可重复。系统时钟倒退时保持度不超过 100%，也不提前强化。

## 永久遗忘与上下文清理

满足以下任意条件即删除事实：

1. 距离最后一次有效学习/强化至少 **30 天**，且保持度 **低于 5%**。
2. 距离最后一次有效学习/强化至少 **180 天**，无论过去强化过多少次。

新记忆在没有复习时第 30 天达到删除条件；强化过的记忆可保持更久。待办事项（`todo:` key 或 `todo` 标签）作为任务数据保留。时间无法解析或指向未来的记录不会因为时间异常被误删。规则集中在 `src/memory.cpp` 的 `memoryExpired`，以 UTC Unix 秒计算，无需额外依赖或后台计时线程。

内置适配器在启动初始化、聊天前、记忆读取/写入及摘要生成前按需清理。电脑关闭或程序闲置时不运行清理；下一次上述操作会补做。删除、摘要失效和上下文起点更新在同一个数据库锁内完成，一次写盘；重复清理没有额外写入。

清理会让相关会话重新开始模型上下文：删除会话摘要，将 `memory_context_after_seq` 设置为清理时的最后消息序号，同时推进摘要游标。角色级记忆对应该角色的全部会话，会话级记忆只影响该会话。其余角色/会话不受影响。

**权衡：相关会话中此前的其他短期上下文也会退出模型输入。** 这是为了避免摘要中的改写表达、工具结果或历史消息再次带回已删除事实。旧聊天记录仍可在界面查看，但不再自动进入提示词或新摘要；有效的结构化事实仍可正常检索。清理后新发出的消息照常处理。会话上下文版本也会持久化，旧的并发摘要/状态更新不能覆盖新的清理边界。这里的永久遗忘指长期事实删除及模型上下文隔离，不是擦除聊天存档；用户再次主动提供内容时可以重新学习。

是否自动保存新事实仍由现有 `remember` 工具和角色设定决定。

## 持久化与适配器

内置 `json` / `memory` 适配器支持字段 `last_reviewed_unix`、`half_life_hours`、`review_count`。JSON 文件重启后继续沿用原强度和计时起点。旧记录从 UTC `updated_at`（缺失时使用 `created_at`）计算年龄，达到条件也会清理；无法解析的旧时间按新记忆处理，首次有效复习建立新起点。

`IDatabase::reviewFact(expected, now)` 是可选适配器接口。内置实现持锁检查事实身份、内容和复习状态，避免并发请求重复强化或把旧回忆套到更正后的事实。自定义适配器（包括 PostgreSQL 示例）默认仅支持基于 `updatedAt` 的衰减检索；要持久化强化，需保存以上字段，并重写此方法，在事务中检查快照、调用 `reinforceMemory`、保存更新，同时在 upsert 中处理重复学习及内容更正。返回 `true` 表示确实发生强化；纯浏览 `listFacts` 不应强化。

自定义适配器若需要永久清理，须实现可选 `IDatabase::pruneExpiredFacts(now)`：使用 `memoryExpired` 判断，在事务中删除事实并更新相关会话的摘要、摘要游标、`memoryContextAfterSeq` 和 `memoryContextVersion`。`updateSession` 必须拒绝用旧上下文版本恢复摘要。默认方法返回 0，保证旧适配器继续编译，但不会自动删除数据。聊天侧会读取当前会话的上下文边界，因此适配器必须持久保存这些字段。

`MemoryService` 与 `JsonFileDatabase` 支持可选时钟注入，默认使用系统 Unix 秒。测试使用同一模拟时钟，覆盖衰减、间隔强化、防刷、删除后的重新学习、内容更正、跨角色/会话隔离、旧格式迁移、删除落盘、启动清理、待办保留、并发旧快照保护，以及过期内容不再进入模型或新摘要。
